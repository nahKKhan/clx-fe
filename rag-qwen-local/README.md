# 현재 RAG 동작 (최신)

매뉴얼 질문(`/api/ask`)과 NASA 임계값 초과 시점(`/api/ims/analyze`)은 검색된 문서 근거를 로컬 Ollama 모델에 전달하여 매 요청마다 한국어 답변을 생성합니다. 이전 버전의 미리 작성된 한국어 문구를 답변으로 선택하는 방식과 베어링 고정 점검 카드 표시는 사용하지 않습니다. 아래의 과거 버전 설명은 이 항목보다 우선하지 않습니다.

- 검색은 기존 TF-IDF 및 문서의 검토된 표-해결코드 연결을 이용합니다. CLP 검색 인덱스에는 검색 보조용 한국어 요약이 남아 있으나 생성 답변의 근거 텍스트로 전달하거나 답변으로 반환하지 않습니다. 베어링의 원인군 4개 연결은 아직 수동 구축된 검색 범위입니다.
- RMS 계산과 통계 판정은 프로그램이 처리합니다. 기준 구간 또는 임계값 이하에서는 이전과 같이 문서 검색을 생략합니다. LLM이 생성한 답변의 정확성이나 출처를 자동으로 보장하지 않으므로 원문과 함께 확인해야 합니다.
- Ollama 서버와 모델이 필요합니다. 기본 모델은 `qwen3:8b`이며, RAG 서버 시작 시 `OLLAMA_MODEL`과 `OLLAMA_URL`로 변경할 수 있습니다. LLM 서버 오류 또는 출력 잘림은 HTTP 503과 함께 사용자에게 알립니다.

실행 (각각 별도 터미널):

```sh
ollama serve  # 이미 실행 중이면 생략
# 프로젝트 폴더에서
/Users/changwoo/Downloads/skf_rag_mvp/.venv/bin/python -m uvicorn rag.server:app --host 127.0.0.1 --port 8011
# 다른 터미널에서
npm run dev
```

# 회전기계 AI 진단 시스템 v4

역할별 업무 공간을 연결하는 React/Vite 로컬 프로토타입입니다.

- `#home`: 통합 현황, 역할 선택, 설비 상태
- `#engineer?asset=COMP-02`: 알람 필터, 설비별 트렌드, 기간 선택, 데모 대화, 근거 열람
- `#maintenance?asset=COMP-02`: 체크리스트, 점검·조치 기록, 편집 가능한 보고서, TXT 다운로드
- `#manager?asset=COMP-02`: 보고서 및 리스크 검토, 후속 조치와 의견 저장

`npm run dev`로 실행하고 터미널에 표시된 로컬 주소를 여세요. `npm run build`로 배포용 정적 파일을 생성합니다.

설비별 기록은 localStorage의 `plant-work-v4`에 저장됩니다. 같은 브라우저/주소에서만 공유됩니다. 역할 선택은 데모 화면 전환이며 로그인·권한 제어가 아닙니다.

4대의 가상 설비와 대표 센서 각 1종, 최근 1시간/30분을 제공합니다. 대화는 키워드 기반이며 실제 LLM, RAG, 실시간 센서, 작업 지시 시스템 연동은 없습니다. 매뉴얼과 임계값은 데모용입니다. 보고서 차트는 화면 미리보기로 제공되며 TXT에는 포함되지 않습니다. 점검 기록 수정 후 보고서를 다시 생성하면 최신 내용이 반영됩니다.

확인: Vite production build, 브라우저에서 역할 전환, 점검 입력, 보고서 생성 및 관리 부서 전달. 테스트용으로 명시된 예시 기록이 로컬 미리보기에 남아 있을 수 있습니다.

## NASA IMS 실제 분석 및 SKF 문서 검색

사이드바 **NASA · RAG 분석** (`#analysis`)에서 실행 결과를 확인합니다.

- IMS `2nd_test` 984개 파일, 첫 번째 채널(Bearing 1)을 사용했습니다.
- 파일별 20,480개 수치의 RMS를 계산합니다. 속도 mm/s로 환산하지 않습니다.
- 최초 100개가 정상이라는 가정하에 평균 + 3 × 표본 표준편차(ddof=1)를 계산합니다. 기준 구간을 이상 집계에서 제외합니다.
- 실제 결과: 임계값 0.0812796723, 평가 884개 중 451개 초과, 최초 2004.02.15.23.52.39. 이는 고장 확정이나 공식 경보 기준이 아닙니다.
- SKF 매뉴얼 전체 본문과 구조화한 고장표를 TF-IDF 단어/문자 혼합 검색합니다. 진동 이벤트는 매뉴얼 적용 범위를 벗어나므로 조치를 생성하지 않습니다.
- 가상 SKF 온도 72°C는 p.52 Table 18 과온 항목을 검색하며, 냉각 및 차단 온도 미만에서 오류 확인·재설정을 안내합니다. 70°C는 매뉴얼 공장 설정이며 실제 장비 설정을 대체하지 않습니다.
- 답변은 근거 제한형 템플릿입니다. LLM/임베딩 API 또는 실시간 센서 연결은 없습니다. 화면은 Python 실행 결과를 읽으며 슬라이더는 저장된 측정 시점 탐색용입니다.
- 기존 가상 설비와 규칙 기반 챗봇은 별도 기능입니다.

### 다시 실행

입력 파일: `data/ims/2nd_test/`의 타임스탬프 파일과 `data/skf_clp_touch_v07.pdf`. 원본은 Downloads의 IMS/2nd_test.rar 및 기존 skf_rag_mvp에서 복사했으며 원본을 수정하지 않았습니다. macOS에서는 `/usr/bin/tar -xf /path/to/2nd_test.rar -C data/ims`로 추출할 수 있습니다.

다른 설정: `python scripts/analyze_ims.py data/ims/2nd_test --channel 0 --baseline-files 100 --sigma 3` (채널은 0부터 시작).

출력: `public/analysis/ims-result.json` (전체 RMS 시계열, 검색 Top-5, 근거 ID, 매뉴얼 SHA-256). 데이터 재생성 후 정적 배포에는 `npm run build`를 다시 실행하세요. 원본 데이터와 매뉴얼은 `.gitignore` 대상이므로 새 환경에 별도 준비해야 합니다.

## NASA · RAG 분석: SKF 매뉴얼 질의 화면

첨부 SKF RAG MVP처럼 질문할 때마다 API가 실제 검색을 실행합니다. NASA · RAG 분석 화면의 **SKF CLP Touch 매뉴얼 RAG MVP**에서 한국어 질문, 답변, Top-5 원문, 페이지별 로컬 PDF 링크를 제공합니다. 기존 우측 Plant Copilot은 별도 규칙 기반 데모입니다.

터미널 1 (프로젝트 폴더에서):
```sh
/Users/changwoo/Downloads/skf_rag_mvp/.venv/bin/python -m uvicorn rag.server:app --host 127.0.0.1 --port 8011
```
터미널 2: `npm run dev`. 접속: `http://127.0.0.1:5173/#analysis?section=manual-rag`.

독립 가상환경을 준비했다면 위 Python 경로를 `.venv/bin/python`으로 바꾸세요. Vite 개발/미리보기 서버는 `/api`를 8011 포트로 전달합니다. 정적 파일만 배포하면 API는 동작하지 않으며 배포 서버에서도 별도 프록시가 필요합니다.

기본 응답은 첨부 MVP의 근거 기반 fallback입니다. 선택적으로 서버 시작 시 `USE_OLLAMA=1 OLLAMA_MODEL=qwen3:8b`를 설정하면 로컬 Ollama를 사용합니다(모델 설치/서버 실행 필요). 진동·IMS 질의에는 문서 범위 제한을 적용합니다.

### 선택한 NASA 데이터로 RAG 검색

NASA · RAG 분석에서 슬라이더로 시점을 선택한 뒤 **이 시점 분석 · RAG 검색**을 누릅니다. `/api/ims/analyze`가 선택 인덱스의 저장된 실측 RMS, 임계값, 기준 대비 비율, 직전 최대 6개 평균 대비 변화를 계산하여 검색 질의에 포함합니다. 관측 결과와 Top-5 검색 후보를 함께 표시합니다. 시점을 변경하면 이전 결과는 사라지며 다시 검색해야 합니다. 첫 시점은 이전 데이터가 없고, 최초 100개는 기준 구간으로 이상 판정을 제외합니다. 시간 간격을 가정해 변화율을 시간당 속도로 해석하지 않습니다.

이 연결은 실제 데이터 문맥을 검색에 사용하지만 SKF 윤활 펌프 매뉴얼의 적용 범위를 넓히지는 않습니다. 현재 진동 이벤트의 조치는 근거 없음으로 제한됩니다. 베어링 진동 진단 문서 추가가 필요하며 LLM 없이 동작합니다.

### 베어링 매뉴얼 연동 업데이트

NASA 시점 분석은 이제 `data/skf_bearing_damage.pdf`의 SKF Bearing Damage and Failure Analysis를 검색합니다. 기존 CLP Touch 자유 질문/가상 온도 기능은 기존 펌프 매뉴얼을 유지합니다.

`rag/bearing.py`는 전체 PDF를 페이지 단위로 청킹하고, 검토한 p.12 Table 1c의 네 가지 원인군(윤활, 고형 오염, 끼워맞춤, 박리)을 Table 2 해결 코드 및 p.14–15, 23, 24, 27과 연결합니다. 시점 분석에서는 이 구조화 지침 안에서 검색 순서를 정하고 관련 본문을 함께 반환합니다. 전체 원인 목록을 망라한 자동 진단이 아니며, 후보 순서는 고장 확률을 뜻하지 않습니다. 한국어 점검 안내는 검토한 문서 요약으로 LLM을 사용하지 않습니다. RMS만으로 후보를 구분하지 않으므로 시점이 바뀌어도 공통 점검 항목은 같을 수 있습니다.

입력 PDF는 사용자가 제공한 `093168a92d25cc46_pdf_preview_medium.pdf`를 복사한 것이며 원본은 수정하지 않았습니다. `/api/bearing-manual.pdf`에서 원문을 제공합니다. 정상/기준 구간에는 해당 지침을 참고용으로 표시합니다. 앞 절의 '진동 이벤트 조치 근거 없음'은 기존 CLP 문서만 사용하던 버전 설명이며 이 업데이트로 대체됩니다.

최근 변경: 기준 구간 및 통계 임계값 이하 시점에서는 RAG 검색을 생략하고 관측 요약만 표시합니다. 일반 점검 후보를 항상 표시하던 기존 동작은 제거했습니다. 기준 구간 이후 RMS가 임계값을 초과할 때만 연결된 문서 지침을 검색·표시합니다.
